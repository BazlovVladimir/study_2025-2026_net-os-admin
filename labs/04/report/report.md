# Цель работы

Целью данной работы является приобретение практических навыков установки Rocky Linux на виртуальную машину с помощью инструмента Vagrant.

# Выполнение

## Установка и базовое конфигурирование HTTP-сервера

После установки группы Basic Web Server были просмотрены каталоги `/etc/httpd/conf` и `/etc/httpd/conf.d`.  
В первом присутствует основной конфигурационный файл `httpd.conf` и каталог `magic`, содержащий определения MIME-типов.  
Во втором находятся модульные конфигурации: `autoindex.conf`, `fcgid.conf`, `manual.conf`, `ssl.conf`, `userdir.conf`, `welcome.conf`.  
Каждый из файлов отвечает за отдельные функциональные модули Apache и подключается директивами из основного конфигурационного файла.

![Просмотр конфигурационных каталогов](Screenshot_1.png){ #fig:001 width=70% }

Для предоставления доступа к веб-серверу был разрешён сервис http в firewalld.  
После применения правил сервер был активирован и запущен.  
Системный журнал подтвердил корректную загрузку всех модулей Apache и отсутствие ошибок при старте.

![Разрешение HTTP и запуск httpd](Screenshot_2.png){ #fig:002 width=70% }

На виртуальной машине client в браузере был открыт адрес `192.168.1.1`.  
Загрузилась стандартная тестовая страница HTTP Server Test Page, которая отображается при корректной установке и запуске Apache на Rocky Linux.  
Это подтверждает успешное функционирование веб-сервера и сетевую доступность сервиса.

![Тестовая страница HTTP-сервера](Screenshot_3.png){ #fig:003 width=70% }

Для оценки работы сервера были просмотрены два журнала:

error_log  
Содержит информацию о запуске httpd, загрузке модулей, политике SELinux и других системных событиях. Ошибок, препятствующих работе сервиса, не выявлено.

access_log  
Фиксирует запросы клиента.  
После открытия тестовой страницы появились записи о запросах к `/`, изображениям и значку сайта.  
Обращение к `favicon.ico` завершилось статусом 404 — стандартная ситуация при отсутствии файла.

# Контрольные вопросы

1. **Через какой порт по умолчанию работает Apache?**
   По умолчанию Apache использует порт **80** для протокола HTTP. Этот порт указан в конфигурационном файле (`Listen 80`) и применяется при обработке обычных веб-запросов.

2. **Под каким пользователем запускается Apache и к какой группе относится этот пользователь?**
   Apache в Linux-системах запускается от имени пользователя **apache** и относится к группе **apache**. Запуск службы под отдельным непривилегированным пользователем повышает безопасность веб-сервера.

3. **Где располагаются лог-файлы веб-сервера? Что можно по ним отслеживать?**
   Логи Apache находятся в каталоге **/var/log/httpd/**.
   Основные файлы:
   — *access_log* — содержит информацию о всех обращениях к веб-серверу: IP-адреса клиентов, запрашиваемые ресурсы, статус-коды, типы браузеров.
   — *error_log* — фиксирует ошибки работы сервера: проблемы с конфигурацией, отсутствующие файлы, сбои модулей, предупреждения.
   По логам можно отслеживать активность клиентов, ошибки конфигурации, попытки несанкционированного доступа и общее состояние сервера.

4. **Где по умолчанию содержится контент веб-серверов?**
   Контент Apache по умолчанию размещается в каталоге **/var/www/html**.
   Для виртуальных хостов создаются отдельные подкаталоги внутри данного каталога.

5. **Каким образом реализуется виртуальный хостинг? Что он даёт?**
   Виртуальный хостинг реализуется с помощью конфигурационных файлов в каталоге **/etc/httpd/conf.d**, где для каждого домена создаётся блок `<VirtualHost>`.
   В нём задаются: доменное имя, корневой каталог сайта, логи и параметры обработки запросов.
   Виртуальный хостинг позволяет запускать **несколько независимых веб-сайтов на одном сервере**, при этом каждому назначается своя директория, свои логи и собственное доменное имя.

# Заключение

В ходе работы настроен веб-сервер Apache с поддержкой виртуального хостинга. Были внесены изменения в DNS-зоны, созданы конфигурации виртуальных хостов и подготовлен их веб-контент. Проверка с клиентской машины подтвердила корректность работы доменных имён и доступность сайтов. Полученные навыки позволяют уверенно развертывать и обслуживать многосайтовые веб-службы.
